# Google Entity Accounts — Setup Runbook (QIC-228)

Single source of truth for every Google product owned by **QIC Trade Systems Limited**. Workspace is already provisioned at `marcello@qictrader.com`; this runbook covers the rest: hardening the Workspace tenant, creating role inbox aliases, attaching a corporate billing profile, and claiming/creating downstream Google products under the entity.

> **Rule:** every Google product touched by QIC Trader gets listed here with **owner**, **purpose**, and a link to where its identifiers live (`ops/credentials-google.md`). Anything not in this file is either unclaimed or undocumented — both are bugs.

## 1. Workspace admin hardening

Goal: no single point of failure on access. `marcello@qictrader.com` is currently the only super-admin. If that account is compromised, locked, or the SIM is lost, the entity loses Google.

### 1.1 Create a dedicated super-admin user

Do this before changing anything else.

1. Sign in to <https://admin.google.com> as `marcello@qictrader.com`.
2. **Directory → Users → Add new user**.
3. Create `admin@qictrader.com`:
   - First name: `QIC`
   - Last name: `SuperAdmin`
   - Password: generated by Workspace, written down once, stored in Bitwarden under `QIC Trade Systems Limited / Workspace / admin@`.
   - **Do not** tick "Ask for a password change at next sign-in" — this account is operator-managed, not human-used day-to-day.
4. After creation: **Users → admin@qictrader.com → Admin roles and privileges → Assign roles → Super Admin**.
5. Sign out, sign in as `admin@` once to set up 2FA and recovery, then sign out and don't touch it except for break-glass.

Cost: this is a billable Workspace seat. Use the cheapest tier (Business Starter at the time of writing) — the account doesn't need Drive storage, just the admin console.

### 1.2 Enforce 2FA on all admins

Workspace-wide policy, not per-user — so it can't be bypassed.

1. **Admin Console → Security → Authentication → 2-step verification**.
2. Scope: select the organisational unit that contains admins (top-level OU is fine for now — only admin accounts exist).
3. **Allow users to turn on 2-step verification** → **On**.
4. **Enforcement** → **On**.
5. **Enforcement period** → set to 0 days (immediate) for admin OU.
6. **Methods**: allow **Security key**, **Google Authenticator app**, **Backup codes**. **Disallow SMS** for admin OU — SIM-swap is the realistic threat for a SA-based fintech.
7. Save. Sign out and back in as both admins to confirm enrolment.

### 1.3 Recovery email + phone on every admin

For each admin account (`marcello@`, `admin@`, and any future super-admin):

1. Sign in as that user → <https://myaccount.google.com/security>.
2. **How you sign in to Google → Recovery phone**: set to a SA mobile number physically held by the account owner. Not a VOIP number.
3. **Recovery email**: a personal Gmail / iCloud / ProtonMail address that is itself 2FA-protected. Not another `@qictrader.com` address — recovery has to work when the domain is locked out.
4. **Backup codes**: download 10 codes, print, store with the founders' physical document set (passport + company registration originals).

Record the recovery email/phone owner (not the value — keep the value in the password manager) in `ops/credentials-google.md`.

### 1.4 Admin account audit (run quarterly)

```text
Admin Console → Account → Admin roles → Super Admin
```

Expected: exactly two users — `marcello@qictrader.com`, `admin@qictrader.com`. Anything else is a finding. Investigate, remove if unauthorised, document if intentional.

## 2. Role inbox aliases

All role aliases route to `marcello@qictrader.com` as the initial recipient. When ops headcount grows, the route changes — the alias does not. Customers, vendors, and regulators only ever see the role address.

### 2.1 Aliases to create

| Alias | Purpose | Initial route |
|---|---|---|
| `ops@qictrader.com` | Internal operations, Heroku/Vercel/Cloudflare alerts, monitoring | `marcello@` |
| `support@qictrader.com` | Customer-facing support, Intercom/Zendesk reply-to | `marcello@` |
| `billing@qictrader.com` | Invoicing, payment processor statements, accounting | `marcello@` |
| `noreply@qictrader.com` | Transactional sender for the app (SendGrid/Postmark From:) | drop — bounce processor only |
| `privacy@qictrader.com` | POPIA / GDPR / regulator contact, abuse reports | `marcello@` |

`noreply@` is a send-only mailbox. It should not accept inbound mail — configure auto-reply pointing senders at `support@`.

### 2.2 Creating the aliases

Google Workspace distinguishes **email aliases on a single user** from **Groups** (which can have multiple members and routing rules). Use Groups for everything except `noreply@` — Groups survive headcount changes without breaking inbound routing.

For each of `ops@`, `support@`, `billing@`, `privacy@`:

1. **Admin Console → Directory → Groups → Create group**.
2. **Group name**: human-readable (e.g. "QIC Support").
3. **Group email**: the alias (e.g. `support`).
4. **Group description**: one line — "Customer support inbound. Routes to active ops staff. Do not delete."
5. **Access type**: **Restricted** (only members can post). Tick **Allow members outside your organisation** so customers can email in.
6. **Create group → Add members**: add `marcello@qictrader.com` as the only initial member.
7. Member role: **Owner**.
8. **Group settings → Email options → Subject prefix**: leave blank.
9. **Conversation history**: **On** — auditability.

For `noreply@`:

1. **Admin Console → Directory → Users → Add new user** → `noreply@qictrader.com`.
   - Reason it's a user not a group: SMTP relay services authenticate as a user mailbox; Groups can't host SMTP credentials. App-specific password is generated against this user.
2. After creation: **Gmail settings → Forwarding and POP/IMAP**: forward all inbound to `support@` and set "delete Gmail's copy".
3. **Vacation responder**: "This mailbox is not monitored. For support, email support@qictrader.com." On indefinitely.
4. 2FA: enforced (same OU policy).
5. App password: generate one for the transactional sender (SendGrid/Postmark) and store in Bitwarden, **not** in this repo.

### 2.3 Verify the routing

After each alias is created, send a test email from a personal account to each role address and confirm `marcello@` receives it. Reply once, confirm the From: on the reply preserves the role address (Group default behaviour, but verify).

## 4. Claim / create checklist

Each downstream product gets its own subsection. Concrete steps, no hand-waving. Where a decision is required, the recommendation is stated with rationale.

### 4.1 Google Ads

**Decision: standalone account now, MCC manager later.**

Rationale: MCC (My Client Center, now called "Manager Account") is useful when you manage Ads accounts for multiple entities or want a clean separation between the agency view and the spending account. QIC currently has one entity, one Ads spend pool. Standalone is simpler and the MCC can wrap it later without losing history.

Steps:

1. Sign in to <https://ads.google.com> as `admin@qictrader.com` (not `marcello@` — Ads ownership follows the account that created it, and `admin@` is the long-lived role).
2. **Start now → Switch to Expert Mode** (top right; "Smart Mode" hides the controls you need).
3. **Skip campaign creation** — link "Create an account without a campaign". You don't want a half-configured campaign live the moment you finish onboarding.
4. **Business information**:
   - Billing country: South Africa
   - Time zone: `Africa/Johannesburg`
   - Currency: **ZAR**. **This is permanent** — you cannot change currency on an Ads account after creation. Confirm twice before clicking.
5. **Submit → Explore your account**.
6. **Tools and settings (wrench icon) → Billing → Summary → Set up billing**:
   - Country: South Africa
   - Tax info: VAT number from §3.1
   - Business name and address: from §3.1
   - Payment method: select the existing entity billing profile from §3.
7. **Account access → Users**:
   - Add `marcello@qictrader.com` as **Admin**.
   - Confirm `admin@qictrader.com` is **Admin** (created the account, should be already).
8. **Account access → Security**: turn on **Require 2-step verification for all users on this account**.

Capture the **Customer ID** (10-digit, format `XXX-XXX-XXXX`, top right of the Ads UI) in `ops/credentials-google.md`.

**MCC later**: when a second entity or an agency relationship appears, create a Manager Account at <https://ads.google.com/home/tools/manager-accounts/>, then send a link request from the manager to the standalone Customer ID. The standalone admin accepts. History and campaigns are preserved.

### 4.2 Search Console

Property: `qictrader.com` (domain property, not URL prefix — domain property covers `www.`, `app.`, every subdomain, and both `http` and `https` in one shot).

1. Sign in to <https://search.google.com/search-console> as `admin@qictrader.com`.
2. **Add property → Domain → enter `qictrader.com` → Continue**.
3. Google shows a TXT record to add at the apex.

The TXT record format is:

```text
Type:  TXT
Name:  @           (or qictrader.com — depends on DNS provider's convention)
Value: google-site-verification=<RANDOM_STRING_GENERATED_BY_GSC>
TTL:   3600        (or "Auto")
```

**Where this goes**: `<TBD: confirm whether qictrader.com DNS is hosted on Cloudflare, Route 53, Cloudns, or the registrar's default nameservers>`. Once confirmed:

- **Cloudflare**: DNS dashboard → `qictrader.com` zone → **DNS → Records → Add record** → Type `TXT`, Name `@`, Content `google-site-verification=...`, Proxy status **DNS only** (proxy is irrelevant for TXT but DNS-only is the correct toggle), TTL Auto. Save. Wait ~30 seconds.
- **Route 53**: Hosted zone for `qictrader.com` → **Create record** → Record type `TXT`, Record name leave blank (apex), Value `"google-site-verification=..."` (Route 53 requires the quotes), TTL 300. Save. Wait ~30 seconds.
- **Registrar default DNS** (Namecheap, GoDaddy, domains.co.za, etc.): each registrar's UI calls this section "Advanced DNS" or "DNS Management". Add a TXT record at the apex with the value. Quote handling varies — paste the value without quotes first, save, and if verification fails, retry with quotes.

After adding, back in Search Console click **Verify**. Verification is usually instant but can take up to 24 hours if DNS is slow to propagate. `dig +short TXT qictrader.com @8.8.8.8` should show the record before retrying.

**Do not remove the TXT record after verification.** Search Console re-checks it periodically and will un-verify the property if the record disappears.

After verification:

1. **Settings → Users and permissions → Add user**: add `marcello@qictrader.com` as **Owner**.
2. **Settings → Ownership verification**: confirm both DNS verification and any backup methods.
3. **Sitemaps → Add a new sitemap**: submit `https://qictrader.com/sitemap.xml` once the frontend generates one. If no sitemap exists yet, flag `<TBD: confirm Next.js sitemap.xml generation in frontend/app/sitemap.ts>` and revisit.

Capture the verified property URL in `ops/credentials-google.md`.

### 4.3 Google Business Profile

A Business Profile is what surfaces in Google Maps and the right-hand panel on branded search ("QIC Trader"). Without one, competitors and scammers can create unverified listings that hijack the brand.

1. Sign in to <https://business.google.com> as `admin@qictrader.com`.
2. **Add your business to Google → Business name**: `QIC Trader`.
3. **Business category**: `Financial Service` (most accurate; `Cryptocurrency Exchange` is not a category Google offers as of 2026-05).
4. **Location**: QIC is online-only. Select **"I deliver goods and services to my customers"** and **uncheck** "I have a physical location customers can visit". Service area: South Africa (country-level).
5. **Contact info**:
   - Phone: `<TBD: SA business number; can be the same as §3.1 billing contact>`
   - Website: `https://qictrader.com`
6. **Verification**: Google offers postcard, phone, or email verification depending on category and country. For SA financial services, expect **video verification** — you'll record a short video showing the registered business address signage and any business documentation. Have the CIPC registration certificate ready. Schedule a 30-minute window when this can be done in one shot; partial submissions time out.
7. After verification: **Info** section — fill out hours (24/7 if the platform is always-on), short description (one paragraph, no buzzwords), services (USDT P2P, ZAR off-ramp, etc.).
8. **Users → Add users**: `marcello@qictrader.com` as **Owner**.

Capture the **Business Profile ID** (visible in the URL when managing the profile, format `accounts/{accountId}/locations/{locationId}`) in `ops/credentials-google.md`.

### 4.4 Google Merchant Center

**Decision: skip. Not applicable to QIC Trader.**

Merchant Center is for retailers selling physical or digital goods (Shopping ads, product listings). QIC Trader is a P2P trading platform — the "product" is a service, not a SKU. There is nothing to feed into Merchant Center.

Re-evaluate if QIC ever launches a branded product line (merch, hardware wallets co-branded with partners, etc.). Until then, do not create an account — empty Merchant Center accounts attract policy-violation flags from automated review.

1. Sign in to YouTube as `admin@qictrader.com`.

   - Add `marcello@qictrader.com` as **Manager** (can upload, edit, manage comments; cannot delete the channel — only Owner can).
   - Leave `admin@` as the Owner.
6. **Channel customisation**: profile picture (logo from `branding/`), banner (`<TBD: produce 2560×1440 banner per YouTube spec>`), description, links to `qictrader.com` and social profiles.
