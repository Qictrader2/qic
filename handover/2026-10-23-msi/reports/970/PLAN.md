1. Daylight on customer pages. ThemeToggle is not offered on customer pages. A stored 'dark' preference is kept in ui-storage and still applies on the pages that honour it.
2. Exact values on the customer surface. --background #F8FAFC, --surface #F1F5F9, --surface-hover and --border #E2E8F0, --input-border #7B8A9C, --card and --popover #FFFFFF, --action #00A3F6 with --action-foreground #FFFFFF, --action-hover #0284C7, --action-pressed #0073AD (text links, outline labels, selected checkbox and radio fills, the current progress step, always with white ticks and dots), --action-subtle #E6F6FF, --foreground #0F172A, --muted-foreground #475569, --text-secondary #556274, --text-placeholder #5F6D80, --success #047857, --success-bg #ECFDF5, --warning #92400E, --warning-bg #FFFBEB, --error and --destructive #B91C1C, --error-bg #FEF2F2, --info #0073AD, --info-bg #E6F6FF, --attention #F59E0B with --attention-foreground #0F172A, --ink-surface #0F172A, --ink-surface-raised #1E293B, --text-on-ink #FFFFFF, --text-on-ink-muted #A3B1C2, --money-in #047857, --money-out #0F172A, --focus #0369A1 and --focus-on-ink #38BDF8. Poppins stays the text face. Figtree (tabular, lining) is used only for the figures inside the shared Amount. The QicTrader name and logo are unchanged.

Status and progress text stay visible. Opacity-only cross-fades are capped at 150 ms. The theme transition does not animate.

Admin, moderator, landing (/ and /lp), help, FAQ, legal (terms, privacy, cookies), contact-us, /escrow, /whatsapp, /verify-email(-pending), /auth/callback/google, the auth pages with their 2FA dialogs, the KYC pages (/account/kyc, /kyc/poa/callback) and the other public content pages keep their current colours, their stored theme, their theme toggle and their behaviour. ## Risks
- Shared primitives cross surfaces. ui/checkbox, ui/loading-button, ui/empty-state, ui/skeleton and ui/button render on admin, moderator, auth, landing and whatsapp pages. Any v5.2 class that is not behind the customer variant restyles those pages, which the card forbids. Mitigations: keep the default-surface class strings byte for byte, cover them with a Jest assertion, and capture /admin, /moderator/disputes, /login and /contact-us on staging.qictrader.com (current frontend) and on the review app.
- Theme forcing. If the head script and ThemeProvider classify a path differently, the page flashes dark or a staff page loses its stored theme. useEffect-based class changes flash during client-side navigation, so use useLayoutEffect. Three components read the raw stored theme (TransactionHistory, MyOffers, AffiliateDashboard), so the provider must report 'light' on the customer surface or they keep their dark branches.
- Sign-in-dependent classification. /loyalty-programme depends on auth-storage before hydration. A stale persisted flag (an expired session) can paint Daylight once before AuthProvider settles and the provider corrects it. This is cosmetic only.
- Legacy alias remap. Pointing --primary, --ring, --input, --muted and the others at v5.2 roles on the customer surface changes every customer component that uses them, including pages not redesigned yet. That is intended (Daylight everywhere on the customer surface), but customer page captures before and after are needed so an unreadable combination is caught, for example text-primary-foreground on a light fill.
- Global reduced-motion block. Following the fix sketch, it also applies on public and staff pages, but only for users who request reduced motion. With the 0.01ms approach, fill-forwards entry animations end visible. animation:none is used only on infinite decorative classes, so nothing is left at opacity 0.
- Keyframe deletion. The 24 removed keyframes have no reference anywhere in the frontend tree by grep. A class name built at runtime would escape the grep, so re-run the grep at implementation time and check the landing pages / and /lp under reduced motion and normally.
- Money display. The Amount component formats server values. Any parseFloat, toFixed or Intl rounding would change a displayed balance, fee or total, or turn a missing value into 0. It must format the decimal string exactly, follow the 'unavailable' rule from lib/wallet-balance-status.ts, and carry a no-rounding property test. In this card it is adopted only on the three sample pages, so no existing money figure changes.
- Root DESIGN.md is outside the frontend repo. The Jest comparison needs a root checkout with the submodule, and root main must keep describing the live UI. Use a root redesign/906 branch. A frontend-only or empty-submodule worktree fails the test by design, not silently.
- Figtree is a new font fetched by next/font/google at build time, like Poppins. A blocked font fetch fails the local build and the review-app build. It must stay confined to Amount figures, as the card limits it.
- Tests. Copy- or class-pinned tests could break: TradeParametersSection's DESIGN.md references, slider-class-overrides reading globals.css, ticket-864 shimmer tests, and the theme-toggle mock in sign-out-entry-points. Adjust them without weakening what they assert. The e2e settings theme probe only logs; group D owns its deletion.
- Release. Merging this to frontend main would ship Daylight to staging and production ahead of Christian's final pack approval, so the PR targets redesign/906 only. The review app redeploys on every push to redesign/906, so a broken merge is visible to every 906 card's QA at once; run the local build and targeted gates before merging. The frontend repo has no CI, so those local gates are the merge proof.
- Review-app QA. It depends on PR #303's review app staying up on the redesign/906 head and on QA sign-in working on its new origin (staging emails a login code to unknown devices; the qic-qa-signin agent's trusted-device method covers it). If the app is down or on an older commit, QA evidence must not be taken from it.
- No money, authorization, state, migration or background-job behaviour changes. risk_areas is explicitly empty: the money-display risk above is display formatting only.
