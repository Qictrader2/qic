## Coordinator item: Escape at 1440 (970 QA item 6)
- Cause: in the base code, the old 819 "Minimum deposit" notice was a second DialogShell with role=alertdialog and dismissible=false (base DepositModal.tsx L595-608). It opened by effect once the minimums query resolved, so it was intermittent, and it moved focus to its own title, outside the Deposit dialog element. While it was up, Escape was prevented (dialog.tsx L347-348), and Radix only dismisses the topmost layer. Both the builder and the reviewer confirmed this from the code.
- Fix: the notice is gone, because B6a says minimums are "shown inline, not in a pop-up that interrupts every network change". I also fixed one focus gap: when the address loaded while Cancel had focus at 1440, focus dropped to the panel. It now returns to the title.
- Test: deposit-escape-958-s3 presses Escape from every focusable element on every step (network, Tron address with and without step 1, Solana address, seen, loading, error, minimum unavailable). It runs at 390 (sheet) and 1440 (dialog) and checks that focus is inside the dialog before each press. It also asserts that no alertdialog or second layer mounts when the minimums arrive late. A child that stops Escape in a capture listener made 12 tests fail, so the test catches it.
- The instruction "Keep the 819 notice's rule (Escape does nothing there)" no longer applies, because the board removes the notice layer. If the coordinator wants the popup back, that contradicts B6a and needs a ruling.
