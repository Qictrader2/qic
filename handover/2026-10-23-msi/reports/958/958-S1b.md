## What changed
1. Transfer, lock and payout variables take optional `idempotencyKey`; useUnlockFunds takes `string | { offerId, idempotencyKey? }`. Each passes the key to the 920 hook's `run` as suppliedKey. No key (all current callers) = old path exactly; empty string = hook's own key. idempotencyKey is a volatile field, so it does not change the payload fingerprint.
2. `clearClientSession` first calls `clearMoneyIntents(useAuthStore.getState().user?.uid)`, before the stores forget the user. Per the 958-S1 round-2 fix, clearMoneyIntents keeps pending (in-flight or unconfirmed) keys and removes never-sent and answered ones. Every sign-out path reaches it (signOutClient for manual, idle, revoked, bootstrap, RequireAuth; http-client force-logout; delete and deactivate account). logout() removes only ALL_STORAGE_KEYS, so the qt:money-intent items survive.
