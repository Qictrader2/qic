## Footer on the six signed-in-only routes: no behaviour change, and why
- **Measured:** a MutationObserver probe (source `s9b-shots/footer-timing-probe.test.ts.txt`) ran on both the base code and a candidate fix. For signed-out visitors on all six routes, the footer appears in the same mutation batch and animation frame as `<main>` content. Signed in, it never appears. There is no late footer to fix.
- **Cause, first render:** `src/store/redux/ReduxProvider.tsx` uses `PersistGate loading={null}`, so the server HTML has no page body; curl of /about and /report shows no `<footer>`. The zustand auth store reads localStorage synchronously when its module loads. So the first render below the gate already has `useAuthHydrated()` true.
- **Cause, server:** the server cannot decide either. Backend auth cookies are host-only on the backend origin (`src/services/auth_cookies.rs` on origin/main, no Domain attribute).
- **Reverted:** I first built a pre-paint `data-auth` attribute plus a CSS-hidden wrapper. That needed shared `src/config/routes.ts` (968's file), so after the measurement I reverted it.
- **Pins:** the comment in `site-footer.ts` names both dependencies (synchronous storage, `PersistGate loading={null}`). Tests pin the synchronous hydration.
- **Seen, not changed:** in the fixture run with all API calls aborted, signed-out /report, /my-tickets, /my-tickets/[id] and /offer/create end on /login. On /offer/create, `RequireAuth` shows only the footer for about 100 ms before the redirect. This is the redirect path, not the footer rule, and it is the same on base.
